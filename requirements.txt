# Weather_Upload_RPi — direct runtime dependencies
#
# Install into the project venv:
#   ./venv/bin/pip install -r requirements.txt
#
# Versions below are the EXACT versions running on the production Pi as of
# 2026-08-06 (captured with `pip freeze`). They are known-good against a live
# Davis 6322C. This repo has no tests, so an unplanned upgrade can break the
# station with nothing to catch it — treat these pins as deliberate.
#
# For a byte-identical rebuild use requirements.lock.txt instead, which pins the
# full transitive tree.
#
# Production environment these were captured from:
#   Raspberry Pi 3 Model B Rev 1.2, Debian 13 (trixie), Python 3.13.5
#
# NOTE: the venv contains Adafruit-Blinka-Raspberry-Pi5-Neopixel and RPi.GPIO
# despite this being a Pi 3B. They are unconditional Adafruit-Blinka
# dependencies, not something this project asked for. Blinka pulls in ~17
# packages to emulate the CircuitPython API across every board it supports;
# this project uses exactly one of them (I2C read of a BME280).
# See temp/AUDIT_PLAN.md item 32 for the proposal to drop the Blinka stack.

# --- Serial link to the Davis 6322C over the RS485 HAT -----------------------
pyserial==3.5

# --- HTTP: Weather Underground upload/download, Mailgun alerts ---------------
requests==2.32.5

# --- BME280 barometric pressure over I2C -------------------------------------
# `board` is imported directly at Weather_Station.py:17 and is PROVIDED BY
# Adafruit-Blinka. Do NOT `pip install board` — there is an unrelated PyPI
# package by that name which shadows Blinka's module and breaks sensor init.
# See DEPLOYMENT.md §10.1.
adafruit-circuitpython-bme280==2.6.30
Adafruit-Blinka==8.69.0
